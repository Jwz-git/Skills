# 技术笔记元数据整理

命令中的 `<skill-dir>` 指本 SKILL.md 所在目录。

在授权范围内批量整理技术笔记的 frontmatter，并用脚本证明正文和无关字段没有被改动。

## 边界

论文笔记里通用字段的跨文件整理（统一 `date`、批量改 `tags` 值等）由本技能处理；不设计论文专属标签体系、笔记结构或论文关系。

按内容判断是否适用，不看目录名。适用：软件、架构、API/SDK、数据库、DevOps/SRE、网络与安全、数据与机器学习、硬件、事故/调试/实验日志、ADR、runbook、项目文档和技术课程笔记。不适用：个人随笔、日记、游记、文学摘录、非技术读后感，与 Markdown frontmatter 无关的配置文件，以及只改正文、标题、文件名或 wikilink 的任务。

所有计划、提问、说明和报告使用简体中文；路径、命令、键名和属性值保持原文，不为“中文化”翻译。

## 授权

| 用户意图 | 默认动作 |
|---|---|
| 检查、统计、列出问题 | 只运行 `audit`，不写文件 |
| 给出范围和旧值 → 新值映射 | 盘点影响后直接执行，不再确认 |
| 要求“整理得更合理”但没给目标体系 | 先给映射方案；分类、语言、层级等主观决定确认后再写 |
| 删除字段、合并值、从文件名推日期 | 规则明确就执行；否则只问那个会改变结果的问题 |
| 改正文 `#tag`、标题、文件名或 wikilink | 超出默认范围，得到明确授权才扩展 |

“看看、检查、统计”不授权写入；“用户可能想要”不是授权；规则已明确时不为形式再次确认。

## 工作流

### 1. 定范围

- 确认根目录、`--include`/`--exclude` 规则和本次允许改动的字段（之后作为 `verify --fields`）；默认不改正文、文件名和未点名字段。
- 脚本递归扫描 `*.md`，跳过以 `.` 开头的文件和目录以及符号链接，不读取 `.gitignore`；需要时用 `--exclude`、`--include-hidden` 调整，并在报告里说明发现规则。
- 在 Git 仓库中先看 `git status`，保留用户已有的无关修改。

### 2. 盘点

```bash
python3 <skill-dir>/scripts/frontmatter_audit.py audit <范围> [--field <键>] [--issues-only]
```

输出 JSON。退出码 0 表示没有 error/warning 级问题，1 表示有，2 表示参数或路径错误。

- `status`：`ok`、`none`（无 frontmatter）、`unclosed`（有开始标记、无结束标记）、`invalid`（YAML 语法错误）、`unsupported`（超出脚本支持的写法）、`decode_error`（不是 UTF-8）。只有 `editable: true` 的文件可以自动修改；其余逐个报告，不猜作者原意。
- `issues`：每项含 `code`、`severity`、行号和中文说明，例如 `duplicate_key`、`scalar_list_property`、`legacy_key`、`case_duplicate_item`。
- `inventory`：各键出现的文件数；`tags`、`aliases`、`cssclasses` 和 `--field` 指定字段的值，区分出现次数与文件数；`tag_variants`（大小写或 Unicode 变体）、`shared_aliases`、`shared_titles`。

脚本只解析 frontmatter 常用的 YAML 子集，只检查顶层键，不检查嵌套映射里的重复键；`unsupported` 的文件需要人工审阅。

### 3. 计划

对每个目标字段给出可复核的计划：

```text
字段: tags
操作: rename | merge | add | remove | normalize
映射: 旧值 -> 新值
影响: 文件数 / 出现次数
格式: 保留原样 | 必要转换 | 统一格式
例外: 不可编辑的文件、无法判定的值
```

合并或删除前列出碰撞和去重结果。删除列表最后一项时，遵循用户或库内既有约定（删除字段还是保留空列表）；推断不出再问。

### 4. 快照、修改、校验

```bash
snap="$(mktemp -d)/before.json"
python3 <skill-dir>/scripts/frontmatter_audit.py snapshot <范围> --out "$snap"
# 按计划修改 frontmatter
python3 <skill-dir>/scripts/frontmatter_audit.py verify <范围> --snapshot "$snap" --fields tags
```

快照必须放在扫描范围之外（脚本会拒绝写进范围内），不含正文，只记录路径、键名、哈希、解析状态和列表属性的值，用完即删。`snapshot` 使用与 `audit` 相同的范围参数，`verify` 沿用快照记录的范围参数。文件很多时可以分批修改，每批后对同一快照运行 `verify`，尚未处理的文件计为未变化。

修改规则：

- 精确重命名用只作用于 frontmatter 的局部 patch；合并或增删时先算语义值，再按该文件原有的块列表或内联列表写法输出，不重排、不重新序列化未授权字段。
- 触及 `tags`、`aliases`、`cssclasses` 时最终值必须是列表；把旧文本值改成列表属于必要格式修复，要计入报告。未授权字段的既有异常只报告。
- 合并后稳定去重，保留首次出现的顺序和拼写；只在用户要求时排序。不自动改变大小写、语言、前导 `#` 或层级 `/`。
- 不修复重复键，除非用户给出保留规则。
- 手写 YAML 值时，对空字符串、首尾空白、会被解析成布尔/数字/日期的字符串，以及含 `: `、` #` 或以 YAML 指示符开头的值加引号并正确转义。
- 只有用户明确要求时才给无 frontmatter 的文件新增模板，直接插在文件开头（BOM 之后），不额外插入空行。

`verify` 退出码 0 表示通过，1 表示有违规，2 表示用法错误。它检查：

- 正文（结束标记之后的字节）、BOM、换行风格，以及 Markdown 与其他文件的集合都没有变；
- 改动的键都在 `--fields` 内，原有键的顺序不变；
- 改过的列表属性仍是列表，没有新增重复项或空项；
- 修改后的 frontmatter 仍可安全解析；改动了 `editable: false` 的文件即为违规。

经授权修改正文（如把正文 `#tag` 迁入 `tags`）时，`verify` 会报告 `body_changed`；逐个核对这些正文 diff 只含授权内容，并在报告里说明。

### 5. 幂等与复核

- 再拍一次快照，按同一规则重放一遍，`verify` 应报告 `changed: 0`。
- 再运行一次 `audit`，确认目标问题已消失，且没有新的 error。
- 在 Git 仓库中查看本次文件的完整 diff，并运行 `git diff --check -- <改动的文件>`。

任何检查失败都先修复再汇报；无法验证的项单列为未验证，不按通过处理。

### 6. 汇报

先给结论，再给证据和例外，至少包括：

- 扫描、修改、未变化、跳过的文件数，以及文件发现规则；
- 实际执行的映射或字段操作，唯一值和出现次数的前后变化（分母为 0 时不算百分比）；
- `verify`、幂等、`audit` 复核和 diff 检查各自的结果；
- 不可编辑的文件（无 frontmatter、边界损坏、重复键、语法错误、超出支持范围）和其他需要用户决定的事项。

## 判断规则

- **Obsidian 列表属性**：`tags`、`aliases`、`cssclasses` 必须是列表，块列表和内联列表只是两种写法；Obsidian 1.9 起不再识别这些属性的文本值（`scalar_list_property`）。
- **旧属性名**：`tag`、`alias`、`cssclass` 在 Obsidian 1.4 弃用，1.9 起不再支持，按“已失效”报告。改名迁移需要授权，并先处理与新字段同时存在的碰撞（`legacy_collision`）。
- **tag**：可含字母、数字、`_`、`-`、表示层级的 `/` 和常见 Unicode 字符（含 emoji），不能含空格，至少有一个非数字字符。大小写不敏感：`Foo` 与 `foo` 是同一个 tag，标签面板显示最早创建时的拼写；全库统一展示大小写是单独的决定。帮助文档未列出的 ASCII 标点只作提示（`tag_unlisted_chars`），不判为无效。
- **aliases**：alias 是当前笔记的替代名称，不是链接。多篇笔记共用 alias 合法，但链接补全会出现多个候选（`shared_aliases`）；显式 `[[目标|别名]]` 链接仍指向写明的目标。不能用“目标文件不存在”判断 alias 孤立。
- **标题和日期**：标题与文件名不同、两篇笔记标题相同都只是候选问题。日期不凭内容猜测，只按用户指定的来源或明确且真实有效的文件名模式补全。
- **结束标记**：Obsidian 只认独占一行的 `---`，`...` 记为非标准结束符。只有目标方言的规范或解析器明确支持时，才对 `audit`/`snapshot` 加 `--allow-dot-end`。
- **自定义字段**：按字段 schema 判断，不把 tag 规则套到所有列表上；自定义列表可以含数字。

## 示例

- **明确映射**：“把后端项目笔记里的 `TODO` 和 `待办` 都合并成 `status/todo`，只改 `Projects/backend/`。”盘点碰撞后直接执行、去重和校验，不再确认。
- **主观分类**：“把架构、数据库和运维笔记的标签整理成合理层级。”先列出现有标签及频次，提出完整的旧值 → 新值映射；语言与层级确定前不写文件。
- **只读审计**：“看看 API 文档和 runbook 的 aliases 有哪些问题。”只运行 `audit`，用中文报告共用 alias、类型异常和解析失败，不把 alias 当链接去检查目标文件。
