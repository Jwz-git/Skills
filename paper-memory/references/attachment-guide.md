# 论文图片附件规范

在创建、更新、提取、重裁或迁移论文图片时使用本文档。本文只管理图片；PDF 原文继续留在 profile 指定的论文来源目录，不随图片迁移。下述 `assets/<noteFileName>/` 是适用于本地 Markdown/Obsidian 的推荐布局，只有 profile 采用该布局时才是要求；Notion 等平台使用对应附件机制并验证可访问。

## 1. 目标布局

本地资料库尚无既有约定时，可向用户建议笔记同级、按笔记名隔离的目录：

```text
<笔记所在目录>/
├── CLIP.md
└── assets/
    └── CLIP/
        ├── fig1_overview.jpg
        └── fig2_training.png
```

对应的 profile 设置为 `attachments.root_pattern: ./assets/${noteFileName}`，其中 `${noteFileName}` 是不含 `.md` 的文件名。profile 中的相对 `root_pattern` 一律相对于笔记所在目录。

如果 Vault 使用附件插件（如 Custom Attachment Location）：

1. 读取插件配置，确认其实际展开的附件目录（按展开后的目录比较，不逐字比较变量写法）。
2. 两者指向同一目录时直接沿用。
3. 不一致时先报告差异；不要静默修改插件配置，也不要擅自把现有附件迁移到另一套规则。

## 2. 链接格式与排版铁律

当 profile 的 `attachments.link_style` 为 `markdown` 时使用：

```markdown
![图 1：CLIP 对比预训练与零样本分类推理流程](./assets/CLIP/fig1_overview.jpg)
```

规则：

- **语法一致**：选择标准 Markdown 时，不混用 Obsidian 专有图片嵌入 `![[...]]`；选择 `wiki` 时使用 `![[...]]`。
- **路径规范**：使用从笔记到图片的相对路径；profile 的 pattern 含 `./` 时显式保留；路径中的空格、逗号等字符做 URL 编码（如 `%20`、`%2C`）。
- **独立成段（禁止行内嵌图）**：每张图片必须独占一行，前后各空一行。严禁把 `![...](...)` 塞进段落句子或括号中间（如 `见首图 ![...](...)`、`（参见下图 ![...](...)）`），否则渲染时大图会在句子正中炸开，严重破坏阅读流。
- **单篇唯一引用（禁止重复嵌图）**：同一张图在同一篇笔记中**只嵌入一次**，放在最贴合的章节（通常总体架构图放「方法流程」开头，局部图放对应模块或实验节）。禁止顶部先放一张首图、到「方法流程」里再嵌同一张。
- **可读图注**：`alt` 文本用简洁、准确的中文概括图号与内容，严禁机械照抄文件名（如 `fig1_overview`）或尺寸数字（如 `860x628`）。
- **稳定命名**：文件名优先使用可读的 `figN_简短说明.ext`，不要仅用时间戳命名。
- **链接解耦**：图片链接与论文关系链接分别遵循 `attachments.link_style` 和 `links.style`，不要互相套用语法。

## 3. 原图提取与质量复核

架构图和流程图优先使用论文原图：

1. 先定位图号、图题与所在页。
2. PDF 中的架构图常由矢量路径与文字组合而成，仅提取内嵌光栅对象往往残缺。优先用环境中已有的渲染工具（如 PyMuPDF/`fitz`、`pypdfium2`、`pdftoppm`）渲染整页，分辨率以图中最小文字清晰可读为准（通常 240–300 DPI）；需要安装新工具时先征得用户同意。
3. 精准裁剪，而不是保存整页：
   - 彻底去除页眉、页脚、页码、相邻栏正文和不影响理解的大块空白；
   - 完整保留图形、所有子图、图例、坐标轴标签、箭头、模块文字及完整图题（特别留意最顶部标题与图题最后一行是否被切半）；
   - 四周保留少量均匀白底安全边距（如 16–24 px），避免文字或线条贴边，并确保浅色背景不依赖透明通道（避免暗色主题下黑字不可见）；
   - 若图题与图形跨栏或相距过远，优先保证图形完整，在 `alt` 或正文中补充图号与含义，不拼接误导区域。
4. **原始分辨率视觉复核**：裁剪完成后必须以原始分辨率肉眼检查每张图，确认：无页眉/正文残留、无被切掉的标题/轴标签/图题、文字清晰可读。不能仅凭脚本成功退出判断质量。
5. 先写入临时目录；确认清晰、完整且将被引用后，再移入目标附件目录。
6. 同一笔记只保留对理解研究问题、总体流程、关键模块或核心实验真正有帮助的图，不为凑数量保存装饰性插图。

## 4. 迁移既有图片

迁移前先运行只读审计脚本（第 6 节），区分：

- 已引用且只属于一篇笔记的图片；
- 被多篇笔记共享的图片；
- 未引用图片；
- 无法解析、存在歧义、位置不符、同篇重复引用或行内嵌入的链接。

执行规则：

1. 只自动迁移“已引用且只属于一篇笔记”的图片。
2. 共享图片默认保留原位并报告；是否复制到各笔记目录由用户决定。
3. 既有未引用图片保留原位并报告，不把“未引用”等同于“可删除”。
4. PDF、PPT、数据文件等非图片附件不参与图片迁移。
5. 移动前检查目标文件是否存在；同名但内容不确定时停止并报告冲突，不覆盖。
6. 移动图片后，在同一操作中更新引用为 profile 规定的链接格式，并顺手消除重复引用与行内嵌入。

## 5. 清理边界

可直接删除的内容仅限本次任务创建的临时渲染页和临时裁剪图。对于任务开始前已存在的文件：

- 不因“看起来不重要”而删除；
- 不因当前没有 Markdown 引用而删除；
- 将候选孤立图片、位置和判断依据报告给用户，由用户决定是否清理。

## 6. 审计与完成验证

本地 Markdown/Obsidian 且 `attachments.mode: local` 时，迁移或批量整理前后各运行一次只读审计：

```bash
python3 <skill-dir>/scripts/audit_image_attachments.py <Memory 根目录> [--scope <子目录>] [--json]
```

审计规则：

- 检查指向图片文件（png、jpg、gif、svg、webp 等）的本地引用，包括 Markdown 图片、`![[...]]` 和 HTML `<img>`；跳过 URL、`data:` 链接以及代码块和行内代码中的示例。
- 显式路径只按路径解析，找不到即报告断链，不按文件名猜测；大小写不一致也报告为断链。
- 只属于一篇笔记的图片，其父目录必须等于 `root_pattern` 展开后的目录，否则报告为位置不符；共享图片和未引用图片单独列出。
- **排版质量检查**：同一篇笔记重复嵌入同一张图片时报告 `duplicate_references`；图片未独立成行（嵌入句子或括号内）时报告 `inline_images`。
- 退出码：`0` 无需修复；`1` 存在断链、歧义、位置不符、同篇重复引用、行内嵌图、无法读取的笔记，或 `link_style: markdown` 下的 `![[...]]`；`2` 参数或 profile 错误。

完成前确认：

1. 统计移动/重裁的唯一图片数、修改的笔记数和图片引用总数。
2. 目标范围内断链、歧义、位置不符、重复引用和行内嵌图均为 `0`。
3. 新裁剪或重裁图片已逐张原始分辨率视觉复核。
4. 共享图片、未引用图片和无法解析的链接已报告，未被静默删除。
5. PDF 和其他非图片附件没有移动。

交付时分别报告“盘点基线”“执行的移动/修改”“验证结果”和“保留未处理的例外”。
