# 论文图片附件规范

在创建、更新、提取或迁移论文图片时使用本文档。本文只管理图片；PDF 原文继续使用 profile 中的论文来源位置。下述 `assets/<noteFileName>/` 是适用于本地 Markdown/Obsidian 的推荐方案，只有 profile 采用该布局时才是要求；Notion 或其他平台使用其附件机制，并验证引用可访问。

## 1. 目标布局

本地资料库尚无既有约定时，可以向用户建议笔记同级、按笔记名隔离的目录：

```text
<笔记所在目录>/
├── CLIP.md
└── assets/
    └── CLIP/
        ├── fig1_overview.jpg
        └── fig2_training.png
```

对应的 profile 设置为 `attachments.root_pattern: ./assets/${noteFileName}`，其中 `${noteFileName}` 是不含 `.md` 的文件名。profile 中的相对 `root_pattern` 一律相对于笔记所在目录。

如果 Vault 使用附件插件（如 Custom Attachment Location）：

1. 读取插件配置，确认它实际展开的附件目录。插件的变量写法可能与 profile 不同，按展开后的目录比较，不逐字比较。
2. 两者指向同一目录时直接沿用。
3. 不一致时先报告差异；不要静默修改插件配置，也不要把现有附件迁移到另一套规则。

## 2. 链接格式

当 profile 的 `attachments.link_style` 为 `markdown` 时使用：

```markdown
![CLIP 训练与零样本分类流程](./assets/CLIP/fig1_overview.jpg)
```

规则：

- 选择标准 Markdown 时，不混用 Obsidian 专有图片嵌入 `![[...]]`；选择 `wiki` 时使用 `![[...]]`。
- 使用从笔记到图片的相对路径；profile 的 pattern 含 `./` 时显式保留。路径中的空格等字符按 URL 编码（如 `%20`）。
- alt 文本描述图片内容，不只写“图片”或机械复制文件名。
- 文件名优先使用稳定、可读的 `figN_简短说明.ext`；不要仅使用时间戳命名。
- 图片链接与论文关系链接分别遵循 `attachments.link_style` 和 `links.style`，不要互相套用语法。

## 3. 原图提取

架构图和流程图优先使用论文原图：

1. 先定位图号、图题和所在页。
2. PDF 中的关键图可能由矢量路径与文本组合而成，只提取内嵌图片对象常常不完整。此时用环境中已有的 PDF 渲染工具渲染整页，分辨率以图中最小文字清晰可读为准（通常不低于 200 DPI）；需要安装新工具时先征得用户同意。
3. 适当裁剪，而不是保存整页：
   - 去除页眉、页脚、页码、周围正文和不影响理解的大块空白。
   - 保留完整图形、所有子图、图例、坐标轴、箭头、模块文字、子图编号，以及足以独立理解图片的图题。
   - 四周保留少量安全边距，避免文字或线条贴边；不要为了画面紧凑切掉图例、标注或图题。
   - 若图题与图片跨栏、跨页或相距过远，优先保证图形完整，并在 alt 文本或正文中补充图号和含义，不拼接会误导读者的区域。
4. 裁剪后必须以原始分辨率视觉复核，确认文字可读、内容完整、没有混入相邻图表；不能仅凭自动坐标或文件生成成功判断质量。
5. 先写入任务临时目录；确认图片核心、清晰且将被引用后，再移动到目标附件目录。
6. 同一笔记只保留帮助理解研究问题、总体流程或关键模块的核心图片，不为凑数量保存装饰性插图。

## 4. 迁移既有图片

迁移前先做只读清单（见第 6 节的审计脚本），至少区分：

- 已引用且只属于一篇笔记的图片；
- 被多篇笔记共享的图片；
- 未引用图片；
- 无法解析、存在歧义或目标不存在的链接。

执行规则：

1. 只自动迁移“已引用且只属于一篇笔记”的图片。
2. 共享图片默认保留原位并报告；是否复制到各笔记目录由用户决定。
3. 既有未引用图片保留原位并报告，不把“未引用”等同于“可删除”。
4. PDF、PPT、数据文件等非图片附件不参与仅图片迁移。
5. 移动前检查目标文件是否存在；同名但内容不确定时停止并报告冲突，不覆盖。
6. 移动图片后，在同一操作中把引用更新为 profile 规定的链接格式。

## 5. 清理边界

可以直接删除的内容仅限本次任务创建、且已确认不会使用的临时渲染页和临时裁剪图。对于任务开始前已存在的文件：

- 不因“看起来不重要”而删除；
- 不因当前没有 Markdown 引用而删除；
- 将候选孤立图片、位置和判断依据报告给用户，由用户决定是否清理。

## 6. 审计与完成验证

本地 Markdown/Obsidian 且 `attachments.mode: local` 时，迁移或批量整理前后各运行一次只读审计：

```bash
python3 <skill-dir>/scripts/audit_image_attachments.py <Memory 根目录> [--scope <子目录>] [--json]
```

审计规则：

- 只检查指向图片文件（png、jpg、gif、svg、webp 等）的本地引用，包括 Markdown 图片、`![[...]]` 和 HTML `<img>`；跳过 URL、`data:` 链接以及代码块和行内代码中的示例。路径会去掉 `<...>`、标题和 `#`/`?` 后缀，并做 URL 解码。
- 显式路径只按路径解析，找不到就报告断链，不按文件名猜测。Obsidian 中不以 `./`、`../` 开头的路径先按笔记目录解析，再按 Vault 根目录解析。
- 只有文件名的引用（Obsidian 或 `![[...]]`）先找笔记同目录，再找全库唯一的同名图片；同名图片有多张时报告为歧义。
- 路径大小写与实际文件不一致时报告为断链。
- 只属于一篇笔记的图片，其父目录必须等于 `root_pattern` 展开后的目录，否则报告为位置不符；共享图片和未引用图片单独列出。
- `--scope` 只限制报告范围（相对于 Memory 根目录，可重复）；引用关系仍按整个 Memory（Obsidian 为整个 Vault）统计，不会把被范围外笔记引用的图片误报为未引用。以 `.` 开头的目录和文件不参与审计。
- 退出码：`0` 无需修复；`1` 存在断链、歧义、位置不符、无法读取的笔记，或 `link_style: markdown` 下的 `![[...]]`；`2` 参数或 profile 错误。

其他平台使用对应的只读核查方法。完成前确认：

1. 统计移动的唯一图片数、修改的笔记数和图片引用总数。
2. 目标范围内没有断链、歧义和位置不符的图片。
3. 新裁剪图片已做视觉复核：文字可读、内容完整、留有安全边距、未混入相邻内容。
4. 共享图片、未引用图片和无法解析的链接已再次报告，未被静默处理。
5. PDF 和其他非图片附件没有移动。

交付时分别报告“观察到的数量”“执行的移动/修改”“验证结果”和“保留未处理的例外”，不要只说“迁移完成”。
