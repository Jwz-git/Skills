# 压缩与写作指南

执行 `compress` 模式时使用本文档。核心目标是写出**面向人类研究者、清晰易扫读、事实严谨**的论文精读笔记，而不是机械填空的模板报告。下述模块、损失和消融写法适用于计算/机器学习论文；其他学科论文按 [paper-types.md](paper-types.md) 映射到同一套章节骨架。

## 1. 输出粒度

### 1.1 Flash Card（1 分钟速查）

用户明确要求快速复习或极简卡片时使用，只保留：一句话记忆、研究问题、核心洞察、方法流程、主要局限。

模板：[templates/flash-card.md](../templates/flash-card.md)

### 1.2 Standard Memory（默认）

适合长期沉淀的纯粹论文精读笔记。聚焦论文自身的问题、洞察、方法、关键模块、核心公式、实验与边界、局限以及论文脉络。**默认不包含「对我的课题的启发」「主动回忆问题」「尚未解决的问题」「理解更新记录」**——主动回忆在 `review` 对话中交互进行，课题迁移分析仅在用户明确要求时生成，变更说明在对话回复中交代。

模板：[templates/standard-memory.md](../templates/standard-memory.md)

### 1.3 Deep Memory

仅当用户明确要求深度精读、详细推导或代码映射时使用。在 Standard Memory 基础上增加：

- 更完整的公式推导与梯度/数值细节；
- 代码映射或 PyTorch 风格伪代码；
- 详尽的消融与超参数表；
- 复现风险与超参数敏感度分析。

模板：[templates/deep-memory.md](../templates/deep-memory.md)

## 2. 顶部结构与层级规范

清晰的层级让读者在几秒内通过大纲定位章节，不要把所有章节都平铺成一级标题 `#`：

1. **单一 H1 主标题**：全文仅有一个 `# <论文短名>`（如 `# CLIP`、`# CMMLoc`）。
2. **原文入口行**：紧接主标题，一行列出可点击的原文与配套资源，例如：
   `**原文**：[本地 PDF](../论文/CLIP.pdf) · [arXiv](https://arxiv.org/abs/2103.00020)`
   （路径含空格或逗号时做 URL 编码，如 `%20`、`%2C`；核实本地 PDF 真实存在）。
3. **一句话记忆**：
   - Obsidian 或支持 Callout 的平台：使用 `> [!abstract] 一句话记忆`；
   - 纯 Markdown 平台：使用引用块或 `## 一句话记忆`。
4. **树形章节**：所有主章节使用 `##`，子节使用 `###`。

## 3. 各章节写作原则

### 3.1 一句话记忆

- 同时覆盖 **研究问题 + 核心方法 + 主要作用/影响**，禁止只复述标题或写“这篇论文研究了 X”。
- 若核心机制比较抽象，可在其下或方法流程中配一个简短的直观例子（Obsidian 用 `> [!example] 直观例子`），帮助快速建立直觉。

### 3.2 核心洞察

- 控制在 3 条左右核心要点。
- 清楚区分 **研究洞察**（概念或建模层面的核心突破）、**工程实现**（使方法奏效的关键设计）与 **基础组件**（直接复用的常规骨干或损失，不把标准 Backbone 包装成创新）。

### 3.3 方法流程与图表嵌入

- **首选论文原图**：总体架构图独立成段放在 `## 方法流程` 开头；局部图只在能独立解释某个关键模块或核心实验时放入对应章节，不机械搬运所有图表。
- **单篇唯一、独立成段**：每张图片在整篇笔记中**只嵌入一次**，必须独占一行、前后空行；严禁在顶部放一张又在方法流程里重复嵌入同一张，严禁把 `![...](...)` 塞进句子或括号中间。详细提取与校验规则见 [attachment-guide.md](attachment-guide.md)。
- **步骤清晰，拒绝一坨箭头串烧**：把多阶段管线拆成编号步骤或小节（如“阶段一 / 阶段二”），必要时单独说明训练与推理的关键差异，而不是把整条流程挤成五六行 `A → B → C → D` 流水账。

### 3.4 关键模块

- 按 `### 模块名` 组织（或先用紧凑总表概览再拆解核心模块），聚焦真正决定性能的组件，说明：**输入/输出（维度与模态）、核心作用、为何需要、消融或去掉后的实际影响**。
- **拒绝空洞废话**：不要写“去掉图像编码器就无法处理图像”这种毫无信息量的套话；没有具体消融数据或非平凡机制说明时，宁可精简也不凑字数。

### 3.5 训练目标与核心公式

- 只保留直接决定模型行为的核心公式；行内用 `$...$`，块级用 `$$...$$` 独立成块（不使用 `\(...\)` 或 `\[...\]`）。
- 重点讲清**优化方向、关键变量含义以及对特征空间或模型行为的影响**。仅当公式本身属于对比学习/度量学习时说明正负样本定义，不要在普通回归或注意力公式下机械填写“此步骤不涉及正负样本”。
- 综述、教程或纯评测基准类论文若无训练损失，可自然命名为 `## 评测指标与核心定义` 或 `## 训练与微调范式`，不必生硬套壳。

### 3.6 实验证明了什么

- 按核心研究问题拆为 `###` 小节，**优先用 Markdown 表格对比关键基线与消融数字**，避免大段罗列数字。
- 将“比较对象、实验口径、观察结论、能支撑什么、不能外推到哪里”自然融合为流畅的科研表述，不再机械重复五段式填空。
- 任何数字必须附带数据集、数据划分、指标与关键设置；重要口径差异或反过度外推边界可用 `> [!note]` 突出提示。

### 3.7 局限与失效场景

- 写具体瓶颈、产生原因与明确的失效场景，拒绝“计算量大”“仍有提升空间”等空泛评价。

### 3.8 与其他论文的关系

- 按需保留有实质内容的子节（`### 前置基础`、`### 同问题工作`、`### 思想相似`、`### 后续改进`、`### 关键差异`），空子节直接省略。
- **正文用自然中文解释关系**，不在每条末尾挂英文关系键（如 `` `builds-on` ``）。
- **零空双链**：只对知识库中真实存在的笔记使用内部链接（`[[...]]` 或相对 Markdown 链接），库里不存在的外部论文/模型一律加粗或纯文本。详见 [connect-guide.md](connect-guide.md)。

## 4. Frontmatter、标签与文件命名

### 4.1 元数据

元数据字段遵循 profile 的 `metadata.fields`（默认 `title`、`date`、`tags`）：

- `title`：论文完整标题；
- `date`：发表年份或具体日期（`YYYY` 或 `YYYY-MM-DD`）；
- `tags`：分类标签列表；
- 资料库已有字段名时沿用原名；`preserve_unknown_fields: true` 时保留未列出的既有字段。Obsidian 和本地 Markdown 使用 frontmatter，Notion 映射到 database properties。

### 4.2 标签规范

标签用于宽分类，论文间关系用正文与链接表达。标签语言、命名空间和数量遵循 profile；生成或整理标签前执行 [tag-taxonomy.md](tag-taxonomy.md)。

### 4.3 文件命名

遵循 profile；采用 `short-title` 时优先使用稳定简称（如 `CLIP.md`、`LVLM Survey.md`、`VPR Tutorial.md`），避免把超长完整论文标题直接当作文件名与附件目录名。若存在重名，使用 `论文短名-年份.md`（如 `ALIGN-2021.md`）。
