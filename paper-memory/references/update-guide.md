# 笔记更新指南

执行 `update` 模式时使用本文档。修改笔记必须是透明、有记录的过程，而不是静默覆盖。

## 1. 理解更新记录

「理解更新记录」是笔记正文的最后一个顶层章节：Standard/Deep Memory 为 `# 理解更新记录`，Flash Card 为 `## 理解更新记录`。只有 `review.persistence: body` 时，其后还可以有「复习记录」章节。

更新已有笔记时：

1. **不静默覆盖**正文中的已有内容。发现事实错误时可以修正，但必须在记录中写明原内容和修正依据。
2. 在「理解更新记录」中追加一条带日期的记录；章节不存在时按上述位置创建。
3. 笔记已有不同格式的记录时，沿用其现有格式。

### 记录格式

每条记录的标题比「理解更新记录」低一级：Standard/Deep 用 `##`，Flash Card 用 `###`。

```markdown
## YYYY-MM-DD 更新

- **原理解**：此前的理解。
- **新理解**：更新后的观点或事实。
- **修改原因**：变更的上下文或动机（如“组会讨论”“实验中发现模型失效”）。
- **证据**：引用的论文章节、代码文件或实验指标。
- **状态**：从下方状态中选择一个。
```

## 2. 更新状态

| 状态键 | 中文名 | 定义 |
| --- | --- | --- |
| `confirmed` | 已确认 | 经论文正文、官方代码库或可验证的推导明确证实的事实。 |
| `user-understanding` | 用户理解 | 用户对概念的个人直觉或主观重构。 |
| `hypothesis` | 待验证假设 | 需要后续阅读、讨论或实验验证的想法。 |
| `uncertain` | 不确定 | 存在矛盾证据，或细节不可得、未确认。 |
| `deprecated` | 已废弃 | 已被证明错误的先前理解。 |

笔记元数据中的状态类字段只在 `metadata.fields` 包含它时更新，并沿用资料库已有取值；没有既定取值时先询问用户，不自创。

## 3. 不追加记录的维护

### 元数据维护

只整理 `tags` 或其他 frontmatter 属性时，不改变论文事实、用户理解或正文结构，因此：

- 只修改 frontmatter，不改正文。
- 保留 profile 允许的既有元数据字段；不要因模板字段较少而删除 `aliases` 或其他字段。
- 不追加理解更新记录，在交付摘要中报告映射、受影响文件数和验证结果。
- 如果标签调整依赖新的论文事实判断，并同步改变了正文理解，则仍按第 1 节记录。

### 图片附件维护

只移动图片、按 profile 转换图片引用语法、修复路径或审计断链时，没有改变论文事实和用户理解：

- 执行 [论文图片附件规范](attachment-guide.md)，不追加理解更新记录。
- 不借附件维护之机改写正文论述、frontmatter 或标签。
- 在交付摘要中报告移动图片数、修改笔记数、引用验证结果，以及保留的共享/未引用图片。
- 如果替换图片同时改变了对论文方法的解释，则正文变化仍按第 1 节记录。
