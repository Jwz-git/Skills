# 论文关联指南

执行 `connect` 模式或填写笔记「与其他论文的关系」章节时使用。本文定义平台无关的关系判断与链接原则；具体语法由 profile 和平台指南决定。

## 1. 关系判定框架（内部分析用，不把英文键写进正文）

下表用于判断两篇论文之间的逻辑关系与证据门槛，防止把泛泛相关错写成直接继承：

| 关系类型 | 语义 | 成立条件 |
| --- | --- | --- |
| 直接继承（builds-on） | 直接建立在前作核心范式上 | 论文明确采用前作的核心方法或管线 |
| 针对改进（improves） | 针对前作弱点改进 | 能指出被改进的具体限制与对照依据 |
| 跨向扩展（extends-to） | 扩展到新任务、领域或模态 | 核心思想延续但适用范围变化 |
| 组件复用（uses-as-component） | 复用前作模型、损失、数据或工具 | 能指明实际复用的具体组件 |
| 同问题工作（same-question） | 研究问题相同 | 问题一致但技术路线可以不同 |
| 思想相似（similar-idea） | 思路相近 | 无直接继承证据时不得写成直接继承 |
| 能力互补（complements） | 能力互补 | 能说明两者组合各自弥补什么 |
| 结论冲突（contradicts） | 结论或证据冲突 | 明确冲突命题及实验/理论条件 |
| 评测复现（evaluates） | 专门评估或复现另一工作 | 评估对象和口径清楚 |
| 提供资源（provides-resource） | 提供数据集、基准或工具 | 资源被另一工作实际使用 |

谨慎使用“替代（replaces）”：除非范围、条件与实验证据足以支撑，否则写成针对改进并说明适用边界。

**正文表达规范**：写入面向人读的笔记正文时，直接用自然中文解释两篇论文的实质联系，**不要在条目末尾附加英文代码键**（如 ``（`builds-on`）``、``（`same-question`）``）；仅当用户明确要求输出机器可读的结构化图谱数据时才使用英文键。

## 2. 建立关系的证据与链接边界

- 优先依据论文正文、引用上下文、官方代码或可核验的实验设置；“都使用 Transformer”“同年发表”或关键词重叠不足以建立关系。
- 相关性不等于继承；无直接证据时按思想相似描述，不臆造继承关系。
- **零空双链（只链真实存在的笔记）**：内部链接（如 `[[...]]` 或相对 Markdown 链接）**只指向知识库中真实存在的文件**（包括同目录论文笔记、个人分析以及基础概念笔记）。对于库里尚不存在的外部论文或模型，一律用**加粗文本**（如 `**AdaLoRA**`）或普通文本，严禁生成指向不存在文件的空双链，也不要在正文里写“待建卡”。
- 每条关系写清对理解脉络或方法选型的实际意义。

## 3. 平台路由与反向链接

根据 `memory.provider` 和 `links.style` 只读取一个相关指南：

- 本地 Markdown：[platform-markdown.md](platform-markdown.md)
- Obsidian / Wiki Link：[platform-obsidian.md](platform-obsidian.md)
- Notion：[platform-notion.md](platform-notion.md)
- `links.style: none`：只在对话输出中说明关系，不创建链接或反向内容。

`links.backlinks` 的统一语义：

- `maintain`：在获得写入授权且目标笔记真实存在时，同步更新另一端。
- `suggest`：**只在给用户的对话回复中**提供精确的反向更新建议（目标文件、章节位置与建议文本），**绝不把“图谱状态与反向更新建议”写进任何笔记正文**。
- `none`：不创建或建议反向更新。

## 4. 索引

只有 `links.index` 非空时才维护索引。`links.index` 指向索引笔记所在目录、具体索引笔记（如 `00-论文总览.md`）或索引页面；本地相对路径相对于 Memory 根目录。新建索引参考 [templates/index-note.md](../templates/index-note.md)。索引用于按研究脉络与场景快速导航，不复制整篇论文摘要；不要擅自创建 `MOCs/` 等未配置的固定目录。
