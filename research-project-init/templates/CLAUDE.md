# <项目名> — 远端的 Claude Code 工作规则

本文件只在远端维护，不同步到本地。本地 Agent（如 Codex）读的是本地的 `AGENTS.md`，两边各自维护。

## 机器分工

| 机器 | 角色 |
| --- | --- |
| 本地电脑 | 主副本：git 仓库、`AGENTS.md`、<只留本地的东西，如 `paper/`、`plan.md`>；本地 Agent（如 Codex）在这里工作，并负责到 GPU 服务器上跑实验 |
| GPU 服务器 `<服务器上的项目路径>` | 训练、评测、特征提取；保存权重、cache、数据和完整实验产物 |
| 远端（你） | 只做两件事：**分析**（代码、协议、结果）和**改写代码**。要跑的东西写成交接，由用户转给本地 Agent |

本目录是用户从本地用 `<WORK>/sync/sync.sh` 同步过来的镜像。用户下次同步时会先把你新建或修改的文件拉回本地，再用本地版本覆盖这里，所以不要在这里保存"只放在远端"的东西。例外有两个：本文件，以及 `<WORK>/handoff/`（只从这里拉回本地，不会被覆盖）。

## 不要做

- 不跑训练、评测、特征提取或基准测试；不安装依赖，不建虚拟环境，不下载数据或权重。
- 不 SSH 到其他机器，不运行 `<WORK>/sync/sync.sh`，也不使用 git：这里没有 `.git`，不要 `git init`。
- 不删除、不改名文件。需要删除或改名时，写进交接，由本地处理。同步脚本会发现被删的文件，并从本地恢复。
- 不修改已有的实验目录和结果目录（<列出，如 `<WORK>/exp/experiments/*`、`output/*`>）。这些目录绑定了当时的源码和服务器上的运行记录，要改就新建 `_v<N+1>`。
- 不修改外部参考仓库（<列出，如 `<WORK>/Text2Loc/`>），只读参考。

允许的检查只有不产生副作用的语法检查：
- Python：`python3 -c "import ast,sys; [ast.parse(open(f).read(), f) for f in sys.argv[1:]]" <文件...>`（不要用 `py_compile`，会生成 `__pycache__`）。
- Shell：`bash -n <脚本>`。
- 可以写纯标准库的小脚本读取结果文件（`*.md`、`*.json`）做统计。脚本放在本次的分析目录里。

## 这里缺什么

远端没有：`.git`、<只留本地的东西>、`AGENTS.md`、权重、cache、数据，也没有服务器上的完整产物（结果目录里只有摘要和必要日志）。文档里的 `<服务器路径前缀>` 是 GPU 服务器路径，这里不存在。

不要猜测这些缺失文件的内容。需要时直接说明缺什么，或者在交接里请本地 Agent 去查。
