# 知识归档决策与写入规范

决定写回知识库后，完整执行本规范。目标不是保存“这次搜到了什么”，而是把可靠、可复用的知识变成**面向人类阅读与速查**的知识体系的一部分。

## 1. 分开判断内容价值与目标位置

先写一句候选知识的核心命题，再分别回答：

1. **它值得保存吗？** 是否可靠、可复用、非重复、不过度短命。
2. **它属于哪里？** 哪个现有主题能够解释它与其他知识的关系。

不要因为某个实体有名字就为它创建文件。文件表示稳定主题，标题表示主题内的知识点。

## 2. 目标文件选择顺序

按顺序选择第一个合理目标：

1. 已有同义或近义章节；
2. 已有上位主题文件；
3. 已有领域综述或方法文件；
4. 同目录下可扩展的索引/总览页所指向的主题文件；
5. 新建一个能容纳多个相关知识点的稳定主题文件。

为每个候选目标检查：

- 现有内容是否与新知识共享问题域，而不只是出现相同关键词；
- 读者以后最可能从哪里寻找该知识；
- 写入后是否会造成文件主题漂移；
- 是否存在更具体但仍足够宽的主题。

若两个目标同样合理且选择会显著改变知识库结构，先回答用户，再询问归档位置；不要复制到两个文件制造双源。

## 3. 目录选择

先识别知识库是扁平结构还是分层结构。不要因为一般知识分类常识而覆盖该知识库自己的分类法。

1. 从根目录开始，读取目录索引、总览页/README（如存在）和代表性文件。
2. 为候选目录写出一句职责描述，并用实际文件内容验证，而非只看目录名。
3. 选择职责能覆盖候选知识的最深层现有目录；若更深目录只覆盖某个相邻子主题，则停在上一级。
4. 若知识库一直采用扁平文件结构，继续放在现有层级，不自行引入目录树。
5. 只有一个稳定分类已经有多个文件可归入，或有清晰证据会持续容纳多个文件时，才新建目录。
6. 新目录的语言、大小写、编号和分隔符必须继承同级目录惯例。

不要为单个模型、论文、术语或一次搜索结果创建目录。若必须创建目录，同时检查父级索引是否按惯例需要更新。

## 4. 文件命名粒度

使用“可容纳至少数个同类章节的最小稳定主题”作为新文件名。

| 候选知识 | 不推荐 | 推荐方向 |
| --- | --- | --- |
| BERT 的掩码语言建模 | `BERT.md` | `预训练语言模型.md` 或 `自然语言处理.md` |
| FlashAttention 的 IO 思路 | `FlashAttention.md` | `注意力与Transformer.md` 或现有的 `高效注意力.md` |
| Python 的上下文管理器细节 | `contextmanager.md` | `Python.md` 或 `Python资源管理.md` |
| 跨论文可复用的一条实验结论 | 用结论句作文件名 | 研究主题或方法比较文件 |

本规范不新建或改写单篇论文的结构化精读笔记及其图片附件（单篇论文归 `paper-memory`）；但主题笔记中可以自然双链引用库里已存在的论文笔记。

以下条件全部满足时，实体级文件才可能合理：

- 实体本身是知识库长期维护的一等对象；
- 预期会有多个独立章节，而非一段定义；
- 同目录的分类规则明确采用实体级文件；
- 用户没有要求把该类实体放入更宽主题。

用户对命名粒度的明确要求优先于同目录惯例：例如用户要求模型知识放进主题文件时，即使目录里已有其他模型的单页，也不要新建 `BERT.md`。

## 5. 同目录格式继承

新建文件前列出同目录知识文件，并读取至少两个最相近文件；少于两个则读取全部。建立一个简短的“格式画像”：

- 扩展名与文件名语言、大小写、分隔符；
- 是否有 YAML frontmatter，字段、顺序、日期格式（如 `date` / `updated`）和标签风格；
- 是否保留单一 `# 标题` + `##`/`###` 树形层级；
- 是否使用 Obsidian Callout（如 `> [!abstract]`、`> [!example]`、`> [!note]`）；
- 列表、表格、代码块、数学公式（`$...$` / `$$...$$`）的写法；
- 内部链接是标准 Markdown 还是 Wiki Link；
- 引用是脚注、行内链接、文末参考资料还是“来源”小节；
- 同目录是否维护总览索引页（如 `00-基础总览.md`）。

执行规则：

- 主题最相近的同级文件优先于纯粹的多数样式；同级格式不一致时，以主题最接近的文件为第一参考、多数惯例为第二参考，不拼出目录中不存在的混合格式；
- 多个近邻一致时完整复用其骨架；
- 不复制与新主题无关的字段值、标签或占位内容；
- 不为了统一风格而改动现有同级文件；
- 只有空目录或没有任何可参考的知识文件时，才使用简洁 Markdown：单一一级标题、清晰二级章节、短段落与“参考资料”部分。

## 6. 面向读者的表达与可读性规范

笔记是给人快速理解与反复查阅的，写作时遵守以下原则：

1. **去机器标签与工具腔**：严禁在笔记正文中写入 `[AI分析]`、`[本地事实]`、`[外部来源]`、`[待验证]`、`[已核验]` 等方括号标签，严禁写入“经本次外部核验”“本地检索未命中”“由 AI 整理”“旧笔记写错现更正”等会话过程话术。
2. **结构清晰、易于扫读**：
   - 保持单一 `#` 主标题与 `##`/`###` 树形大纲，不平铺多个 `#`；
   - 结论先行，在合适处用 **Markdown 对比表**、**简短直观例子**（若同目录支持 Callout，可用 `> [!example]`）和**选型/避坑对照**替代冗长段落；
   - 数学公式统一使用 `$...$` 与独立成块的 `$$...$$`，确保符号闭合、变量先解释后使用。
3. **零空双链**：所有写入的内部链接（如 `[[...]]` 或相对路径，含 `#标题` 锚点）必须核验目标文件与标题在磁盘上真实存在。知识库中尚未建页的模型、论文或术语一律写加粗或普通文本，绝不制造空双链污染图谱。
4. **顺滑融合，禁止打补丁**：修改既有笔记时重写并理顺对应段落，使新旧内容浑然一体，不要在原句后面硬贴一句与前文拧巴的“更正说明”。若发现并修正了原笔记中的事实错误，把“原表述是什么、为何修改、依据是什么”清晰写在**给用户的对话回复**里，正文只留准确、连贯的表述；但若内容属于用户本人记录的主观判断或待定观点，不要静默覆盖，先在对话中指出冲突或以自然中文并列说明条件差异。

## 7. 合并到现有文件

1. 读取整个目标章节以及前后相邻章节。
2. 搜索新知识的同义词、缩写和旧表述，识别重复或冲突。
3. 将信息放到读者预期的位置：
   - 定义靠近概念介绍；
   - 机制靠近原理；
   - 例子与选型靠近对应方法；
   - 限制与边界靠近适用条件；
   - 来源沿用文件既有格式。
4. 优先改写并合并已有段落；只有真正新增维度时才增加小节，不在文末机械追加重复段落。
5. 不把检索日志、搜索词、浏览过程写进知识正文。
6. 若原文件包含 `updated` 等更新时间属性，按其原有日期格式更新。
7. 目录一贯维护总览索引（如 `00-基础总览.md`）或双向链接时同步更新；否则不要凭空引入新体系。

## 8. 证据与来源

每条持久化的外部关键结论至少对应一个可追溯来源，并按目标文件既有格式（行内链接或文末参考资料）自然收纳：

- 页面或论文标题、作者/机构；
- 正式链接、DOI 或稳定标识；
- 仅当内容本身具有时效性或版本依赖（如框架版本特性、接口变更、政策日期）时，才在正文中标注版本号或“截至 YYYY-MM-DD”；稳定基础理论不必在每段都贴核验日期。

只做必要的短引述，其余使用忠实改写。对推论和适用边界使用“这意味着”“需要注意”“在这些条件下”等自然限定词，不把推论伪装成来源原话。

## 9. 最小改动与验证

写入后逐项检查：

- 新段落是否回答了一个清晰问题，读起来自然顺畅、无机器标签与补丁腔；
- 是否与已有段落重复或前后矛盾；
- 文件主题是否仍然单一，新文件是否真的比新增章节更合理；
- 格式是否与同目录最相近文件一致；
- 所有内部链接（含 `#标题` 锚点）、外部链接与数学公式均可正常解析；
- 若在 Git 仓库中，diff 只包含本次知识增量。

发现目标选错时，先移动本次新增内容到正确位置，再删除仅由本次任务产生的空壳；不要触碰用户既有无关文件。
