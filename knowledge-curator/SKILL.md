# 知识库问答与沉淀

把当前活动目录视为知识库根目录。先用本地材料回答；只有本地证据不足、过时或冲突时才研究外部来源。回答问题与沉淀知识是两个独立决定：问题必须回答，但只保存值得长期复用且证据可靠的增量信息。

**核心原则——对话汇报与知识库正文分离**：
- 回答问题时的**对话回复**用于交代证据来源、检索命中情况、外部核验过程以及为何修正旧表述；
- 写回知识库的**笔记正文**是给人长期阅读与速查的主题文档，不是搜索报告或 AI 审计日志。正文应流畅、克制、排版清晰，严禁塞入机器标签、检索过程话术或自相矛盾的“补丁句”。

命令中的 `<skill-dir>` 指本 SKILL.md 所在目录。

## 边界

- 不按原文归档网页（交由 `article-archiver`），不批量整理 frontmatter（交由 `metadata-tidy`）。
- 已有的论文精读笔记可以作为本地证据读取，也可在主题笔记中自然双链引用，但不新建或改写单篇论文精读笔记（交由 `paper-memory`）。

## 核心流程

### 1. 确定范围

1. 以当前活动目录为默认知识库根目录；用户指定子目录或文件时缩小范围。
2. 运行 `pwd`、`rg --files`，识别笔记、文档、索引/总览页、目录说明和命名惯例。
3. 排除 `.git/`、构建产物、依赖目录、缓存和临时文件。不要把技能自身的说明当成领域知识，除非问题就是关于该技能。
4. 仅在无法可靠确定知识库根目录且不同选择会改变写入位置时询问用户。

### 2. 先检索本地知识

先运行只读检索脚本，再定向读取候选文件：

```bash
python3 <skill-dir>/scripts/search_knowledge_base.py "用户问题" --root .
```

脚本忽略中英文停用词和“如何、区别、原理”等提问用语，中文按双字切分；按 IDF 加权的查询词覆盖率（`coverage`）筛选候选，再按 BM25 得分乘以覆盖率排序。

- 退出码 `0`：有候选达到覆盖率阈值（`--min-coverage`，默认 `0.6`）。每个候选列出 `matched`、`missing` 查询词，以及带行号、段落、幻灯片、表格行或页码的片段。
- 退出码 `1`：没有候选达到阈值，输出 `results: none`；附带的 `weak_candidates` 只部分命中，不能作为依据。
- 退出码 `2`：参数或路径错误，或查询中没有可检索的词。
- 默认跳过以 `.` 开头的文件和目录，需要时加 `--include-hidden`。本技能目录位于知识库内时，用可重复的 `--exclude` 排除它：不含 `/` 的模式匹配任意层级的同名文件或目录（如 `--exclude knowledge-curator`），含 `/` 的模式相对于 `--root` 匹配（如 `--exclude 'tools/skills/**'`）。
- DOCX、PPTX、XLSX、EPUB 直接抽取正文；PDF 优先使用 `pdftotext`，若未安装则自动回退到 Python 的 `PyMuPDF (fitz)` 或 `pypdf` 按页抽取正文；三者均不可用时才降级为仅按文件名匹配并在 `note:` 中说明。`.doc`、`.ppt`、`.xls` 只按文件名匹配。只按文件名命中的文档，先用对应格式工具读取原件，再作为依据；不要用 `strings` 代替可靠解析。

然后：

- 阅读排名靠前的 3–8 个候选及其上下文，不要只依据命中行作答；`missing` 中的关键概念要单独核实。
- 用 `rg -n` 补查同义词、缩写、英文名、旧称和关键实体。
- 记录能直接支持结论的文件、章节和行号，并检查材料日期。

出现以下任一情况，判定本地信息不足：

- 只有关键词提及，没有直接回答问题的内容；
- 关键结论缺少依据，或重要维度明显缺失；
- 来源互相冲突且本地材料无法消解；
- 问题涉及“最新”、当前版本、价格、政策、接口或其他时效信息，而本地材料可能过期；
- 脚本退出码为 `1`，且换用同义词或改写后的关键词重新检索、用 `rg` 定向搜索后仍没有直接相关的内容。

### 3. 用证据回答

- 本地材料足够时，直接回答，不为“显得完整”而额外联网。
- 先给结论，再给依据、边界条件和可验证路径。
- 在对话回答中清楚区分本地文件中的事实、外部来源中的事实、推断和建议。
- 引用本地文件时给出可定位的路径与章节或行号；不要声称未读文件支持结论。
- 材料冲突时分别陈述，不强行合并；说明哪项证据更可靠及原因。

### 4. 必要时研究外部来源

本地信息不足时再联网。技术和学术问题按以下优先级取证：

1. 标准、官方文档、官方数据和原始论文；
2. 作者或机构的一手材料；
3. 高质量综述或可信二手资料。

论文优先读原文的摘要、方法、实验和限制，不只看搜索摘要。时效性问题核对发布日期、事件日期和版本。回答中为外部事实给出链接，并标明哪些结论来自外部补全。

不要把搜索摘要、单一博客观点或尚未核验的推测写成确定事实。无法核验时明确说明缺口。

### 5. 独立决定是否沉淀

仅当新信息同时满足以下条件时写回知识库：

- 超出当前一次性回答，未来很可能复用；
- 能补足现有知识缺口，而不是重复已有内容；
- 有可追溯的可靠来源；
- 结论稳定，或能够用日期、版本清楚限定；
- 不包含凭据、隐私、受限内容或大段受版权保护的原文。

以下情况默认不写入：一次性操作结果、未经核验的主张、纯搜索过程、很快失效且无历史价值的数据、与知识库主题无关的内容、现有文件已完整覆盖的内容。用户明确要求只回答、不改文件时，不写入。

一旦决定写入，必须先完整读取 [references/filing-policy.md](references/filing-policy.md)，再选择目标并编辑。

### 6. 选择目标并安全整合

按 filing-policy 执行，核心是：

1. **现有文件优先**：先找能容纳该知识的现有章节或主题文件，顺滑合并进合适章节。
2. **宽主题优先**：没有合理宿主时才新建文件，并用能容纳多个相关知识点的稳定主题命名，不用单个模型、术语或孤立事实命名（例如 BERT 并入 `预训练语言模型.md`，不新建 `BERT.md`）。不要为单个知识点新建目录。
3. **继承格式且面向人读**：新文件和新章节严格向同目录最相近的文件看齐；结论先行，善用对比表格与直观例子，拒绝大段流水账、机器标签（如 `[AI分析]`、`[外部来源]`）和“旧笔记写错现更正”式补丁句。
4. **零空双链**：所有写入的内部链接（如 `[[...]]` 及其 `#标题` 锚点）必须指向库中真实存在的文件与标题；库里尚未建页的概念或论文用加粗或纯文本。
5. **最小改动**：保留原有 frontmatter、用户观点、有效链接和章节顺序，只做与本问题相关的修改；若同目录有总览页（如 `00-基础总览.md`），新建文件或重大结构调整时同步维护。

### 7. 写后验证并交付

编辑后必须：

- 重读修改段落及前后文，确认语义连贯、无重复、无补丁腔、标题层级清晰；
- 核对写入的所有内部链接（含 `#标题` 锚点）、外部链接、数学公式（`$...$`/`$$...$$`）及重复知识点；
- 在 Git 仓库中运行 `git diff --check` 并审阅本次相关 diff；非 Git 目录下同样完成全文复读与链接/公式自检；
- 不覆盖或整理用户已有的无关改动。

最终回答必须包含：

- 对用户问题的直接答案；
- 主要依据及仍不确定的部分；
- 是否使用了外部信息；
- 若写回：修改或新建的文件路径、归档理由、改动摘要（如修正了哪处旧表述及依据）和新增来源；
- 若未写回：一句话说明未满足哪项沉淀条件。

## 完成标准

- 已先检索本地材料，并能展示可复核的本地依据或明确的未命中结果；
- 外部研究只补足真实缺口，来源层级与问题风险匹配；
- 回答中的事实、推断和建议清晰可区分；
- 写回内容面向人类阅读、可追溯、不重复、无机器标签与空双链，新文件严格继承同目录格式；
- 所有改动均通过定向复读、链接/锚点/公式校验与重复检查。
