# 边界情况处理

只在遇到对应输入时读取本文件。

## 多图输入

- 明显属于同一文档的连续页：按用户提供顺序合并为一个 Markdown；可用 `<!-- 第 N 页 -->` 标记页界，但不要重复页眉页脚。
- 互不相关的图片：分别输出 Markdown。
- 顺序或分组无法从文件名、上传顺序和内容判断，且会改变结果：再询问用户。
- 每张原图都单独运行 `prepare_image.py`，不要只处理第一张。
- 累计读图（含分片）可能超过 20 张时，所有输入从第一张起都加 `--max-edge 2000`。

## 分片顺序与拼接

只有图片超过原生分辨率时才会切分，`files_to_read` 已按阅读顺序排列：

- 只需上下切开（长图）：分片从上到下排列。
- 需要左右切开且切线都落在空白列（如栏间距）：按列优先排列，从左到右逐列、每列内从上到下；各列的上下切线互不相关。
- 需要左右切开且切线穿过内容：所有列共用同一组上下切线，按行优先排列；同一行的左右分片依据 `box` 拼成整行后再读下一行。

切线落在空白处时，相邻分片恰好相接，没有重复内容；找不到足够宽的空白时，切线穿过内容，后一分片会回退一段与前一分片交叠（`box` 相交，`notes` 也会提示）。拼接交叠分片时：

1. 用相同的完整句、表格行或代码行定位交叠区；
2. 只删除能确认完全重复的内容；
3. 不能确认时保留并加 `<!-- possible overlap -->`，不要猜测衔接文本。

## 动画（GIF、WebP、APNG）

Claude 只使用动画的第一帧。`prepare_image.py` 默认也只输出第一帧，并在 `notes` 中报告总帧数。用户明确要求全部帧时加 `--all-frames`，按 `page`（帧序号）逐帧转录；不要把帧之间的变化臆测成文字或事件。

文件交付模式下可在文末注明：

```markdown
<!-- 来源为动画；本次仅转录第一帧。 -->
```

## 多页 TIFF

脚本会展开全部页面，每页分别摆正、转换颜色模式并按需切分；`page` 是页号，同一页的分片相邻排列。默认合并为一个 Markdown；页与页之间只有在内容边界不清时才使用 `---`。

## 旋转、透视与镜像

- `prepare_image.py` 已按 EXIF 方向摆正图片，`box` 与裁剪坐标都以摆正后的图片为准。
- 没有方向标记但文字明显旋转时，把旋转校正后的副本保存到临时目录（不覆盖原图），再对副本运行 `prepare_image.py`，裁剪也基于该副本。
- 文档照片有透视畸变时，可以先校正副本，但不能用几何校正补出原图中不存在的像素细节。
- 镜像文字只有在方向可确认时纠正读取方向；转录内容本身不加“修正后的”猜测。

## 深色背景、低对比度、模糊与过小图片

官方文档提示，Claude 在低质量、旋转或小于 200 px 的图片上更容易误读。分片算法只用于寻找切线，不是 OCR 引擎，也不能证明文字可读。若文字仍不可辨：

- 完全无法确认：`[unclear]`
- 仅能确认一部分：`[partially visible: 可确认部分]`
- 被覆盖或截断：`[obscured]`

不要根据上下文补字。可以在最终交付中报告不确定标记数量。

## 空白图与纯照片

- 真正空白：输出 `> [空白图片：未检测到可转录文字或有语义的视觉内容]`。
- 纯照片：不是空白。快速读取模式下客观说明“未检测到可转录文字”；文件模式下按用户目标嵌入原图或相关区域。

## 损坏或无法读取的文件

`prepare_image.py` 返回 `error` 时，说明具体错误和已确认的文件路径，不要猜测内容。像素数超过 Pillow 安全上限的图片会被拒绝（错误信息含 `decompression bomb`）；这是防护机制，不要擅自关闭，先询问用户。不要尝试绕过 DRM 或访问控制；建议用户提供可正常打开的 PNG 或 JPEG 副本。
