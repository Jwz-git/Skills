# 文章归档

将一个或多个文章 URL 保存为可追溯的 Markdown。默认只去除页面噪声和规范格式，不改写正文。

命令中的 `<skill-dir>` 指本 SKILL.md 所在目录。

## 边界

- 只阅读、总结或翻译链接而不保存时，直接处理，不使用本技能。
- 本技能只按原文归档，不改写、摘要或把内容并入已有笔记，也不转写图片中的文字。

## 配置

抓取前运行：

```bash
python3 <skill-dir>/scripts/archive_config.py resolve --cwd "$PWD"
```

`config` 是生效配置：默认值依次被个人配置和最近的项目 `.article-archiver.json` 覆盖。`configured` 为 `false` 时才算首次使用：只询问本次请求尚未明确的项目（输出目录、资源下载方式、配置保存为项目还是个人范围），再用 `init` 写入；修改个人配置前必须确认。命令、字段和退出码见 [configuration.md](references/configuration.md)。

## 获取原文

先直接读取规范 URL；失败或正文不完整时，再读取浏览器中的可见页面。可以使用用户已有登录状态读取其有权访问的内容，但不得绕过登录、付费墙、验证码、robots 或其他访问控制。处理帖子串、问答页面、需要登录的页面或读取受阻时，阅读 [acquisition.md](references/acquisition.md)。

提取标题、作者、原始发布时间、正文、图片、图注、代码、表格、公式、引用和脚注；排除导航、广告、推荐、评论及其他页面噪声。检查开头、结尾、折叠内容、分页和帖子串连续性。无法确认完整时，停下来询问是否以 `incomplete` 状态保存。

批量处理时，各 URL 独立标记为 `saved`、`incomplete`、`failed` 或 `conflict`，失败项写明可观察到的原因。单项失败不阻塞其他项目，除非继续处理需要新的授权，或剩余项目都受同一阻塞条件影响。

## 保存规则

默认使用经核验的原标题，不另拟标题；正文保持原有措辞、顺序和结构，只修正 Markdown 层级、空白、列表、代码块等格式。除非用户明确要求，不添加摘要、不翻译、不重排、不改写。

frontmatter 只使用以下字段：

```yaml
---
title: ""
author: ""
published: ""
source_url: ""
language: ""
tags: []
---
```

- `title`、`author` 只有明确属于正文主体时才算已核验。
- `published` 只用页面明确关联到该文章或帖子的原始发布时间；不用更新时间、抓取时间、搜索结果日期或从 URL 推断的日期。
- `tags` 根据文章主题提取少量明确标签，无法判断时使用空数组。
- 无法核验的值留空，并在结果中说明，不得猜测。

归档文件名：用户指定时用指定名称，否则用原标题。来源没有标题时（如 X 单条帖子或帖子串），`title` 留空，文件名用经核验的 `<作者> <发布日期 YYYY-MM-DD>`；缺少其中一项或需要区分同名文件时，追加来源的稳定 ID（帖子 ID 或 URL slug）。不得为命名自拟标题。

写入前运行：

```bash
python3 <skill-dir>/scripts/archive_config.py plan --cwd "$PWD" --name "<归档文件名>"
```

- 退出码 `0`：把 Markdown 写到 `markdown`；`assets_dir` 不为 `null` 时，把资源下载到该目录。脚本已清理文件名，过长时按字节截断并标记 `truncated`，以输出路径为准。
- 退出码 `1`：`conflicts` 中的目标已存在，必须停下来询问，不得静默覆盖。
- 退出码 `2`：配置或名称无效，按错误信息处理。

Markdown 中用相对于文章文件的路径 `<assets.directory>/<name>/<资源文件名>` 引用资源；路径含空格时，用 `<...>` 包裹链接目标或把空格编码为 `%20`。下载失败时保留远程 URL 并报告失败。

完成后报告准确文件路径、失败或不完整的 URL，以及无法核验的元数据。
